# webui-theme.txt 文风规范

参考案例原文：`references/sample/achen-theme-description.txt`。写作前至少通读一遍；不确定详略程度时重读对应界面段落校准。模板：`assets/templates/webui-theme.template.txt`。

## 文体规则

1. 中文自然语言叙述，纯文本，不使用 Markdown 标记、表格、代码块、项目符号列表或 JSON。
2. 以长句为主，用逗号连接同一区域内的多个元素；只有切换界面或章节时才换行分段。案例中的典型句式：「左上内容分为三小块，第一小块为展示用户头像，邮箱，下方小字展示用户正在使用的套餐」。
3. 大量使用方位与布局词：最左侧、右侧近邻、图标下发弹出、常驻、左上、左下、右、上下布局、横向排布、下方部分、平铺整个网站、包含标题栏。
4. 保留界面原文案、数值、单位与默认值，例如「在线IP（设备限制）默认0/∞」「佣金比例25%」「返佣比例 25% · 结算以站点规则为准」「您还没有套餐，快去购物吧！」。
5. 交互写成「点击 X，跳转到 Y 功能界面」「点击 X，出现弹窗，包含……」「点击文字可跳转到……」；弹窗内容按字段出现的先后顺序逐一列出。
6. 状态分支写成「如果没有买套餐就显示……，如果用户已有套餐，就展示……」「待支付 / 已完成 / 已取消，这两状态，同时显示……」「无图片url，则显示默认」。
7. 颜色与图标只写可见语义，不写实现属性：绿色图标 正常，红色图标 维修，进度条依据用量占比显示绿、黄、红、暗红。设计 Token 与 CSS 属性留给 `copy-themeUI.md`。
8. 疑问与工具提示按案例写法记录：「？图标展示（……）」，括号内写清提示内容与公式。
9. 结尾保留「细节与修复项」章节，逐条写「修复，……」「优化，……」，覆盖图标来源、背景图缺省、进度条特效、协议提示、favicon 等易遗漏细节。

## 观察与叙述顺序

```text
整体风格一句话
  → 网站全局布局（导航栏、公告栏、背景、右侧工具区、多端）
  → 逐个功能界面（分区 → 小块 → 字段与文案 → 状态分支 → 交互跳转）
  → 界面内弹窗与二级页面
  → 细节与修复项
```

每个界面至少一段；分区复杂的界面（如仪表盘、购物中心、推广中心）按分区分段，但段内仍为连续叙述。

## 章节结构

与模板一致，标题使用裸文本（不带 `#`）：

```text
网站主题风格
网站布局
各个功能界面
<界面名>
<界面名>
……
细节与修复项
```

界面名使用站点上的原文，顺序与导航栏顺序一致；导航切换产生的二级界面紧跟其父界面描述。

## 详略标准

- 每个界面写清：由几大板块组成、板块方位、每板块内的小块、每个字段的名称与默认值、按钮名称与层级、状态分支、跳转目标。
- 案例级别的信息密度：一个复杂界面通常是数百字的连续段落，不省略「右下角」「下方三个按钮」这类位置信息。
- 重复出现的控件（如「立即购买按钮」「查看详情」）每次出现都要写明，不用「同上」。
- 多公告轮询、状态选择、分页、刷新、复制、下载、取消订单等行为必须写明触发方式与结果。

## 禁止项

- 禁止「可能」「大概」「应该是」等推测词；未观察到的内容写「未观察到」并记入 `scan/manifest.json` 的 `gaps`。
- 禁止写 CSS 属性、色值、Tailwind 类名或组件 props；这些属于 `copy-themeUI.md`。
- 禁止把多个界面压缩成一句「其余界面类似」。
- 禁止保留模板中的 `>>` 提示行与 `{{...}}` 占位符。
- 禁止使用 Markdown 表格代替换行叙述。

## 自检

把写好的 `webui-theme.txt` 与案例对照：随机抽取一个复杂界面，检查是否同时具备「分区方位、字段文案、状态分支、按钮与跳转、细节提示」五类信息；缺任一类则回到对应界面补写。
