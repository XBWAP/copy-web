# 组件：word-theme

| 元信息 | 值 |
| --- | --- |
| 组件名 | `word-theme` |
| stage | 2 |
| 版本 | 1.0.0 |
| 依赖 | `web-scan` 的 `webui-theme.txt` 与 `scan/manifest.json` |
| 输入 | `webui-theme.txt`、`scan/manifest.json`、可选 `scan/dom/*.json` |
| 输出 | `copy-themeUI.md` |

## 职责

把叙述式的 `webui-theme.txt` 转写成一份详细描述、系统性、可被直接实现的 WebUI 主题规范 `copy-themeUI.md`：定义设计语言、设计 Token、布局系统、组件清单、逐页规格、状态与交互、动效、静态资源映射与验收清单。该文件是 `web-maker` 的唯一需求来源。

## 输入契约

| 输入 | 作用 |
| --- | --- |
| `webui-theme.txt` | 唯一需求来源，逐条编号后不得遗漏 |
| `scan/manifest.json` | 提供界面清单、截图路径与静态资源路径映射 |
| `scan/dom/*.json` | 补充原文未写明的计算样式数值 |
| `assets/templates/copy-themeUI.template.md` | 章节与字段骨架 |

## 输出契约

`<outputDir>/copy-themeUI.md`，结构化 Markdown，按模板章节组织；每个规范性条目都标注来源编号，末尾含需求追踪矩阵与验收清单。

## 前置条件

1. `webui-theme.txt` 已通过 `web-scan` 的质量检查。
2. `scan/manifest.json` 可读，资源路径可解析。
3. 已读取 `assets/templates/copy-themeUI.template.md` 与 `references/pipeline.md` 的文档契约。

## 执行流程

1. **编号**：通读 `webui-theme.txt`，按界面与描述条目生成稳定编号 `D-001`、`D-002`……；把「细节与修复项」也纳入编号。编号贯穿全文，后续不得重排。
2. **提取设计语言**：归纳主题名称、视觉气质、参考风格与不适用项，写入第 1 章，每条附来源编号。
3. **数值化设计 Token**：把叙述中的风格描述转成具体参数：色彩（画布、卡片、品牌、文字、注释、状态色，含透明通道）、字体栈与字重/字距、字号阶梯、圆角、间距、容器宽度、阴影、模糊、发丝线、动效缓动与时长。原文未给出数值时，从 `scan/dom/*.json` 与截图取证据并标注证据路径；仍无法确定时写入「待确认」表并**暂停向使用者确认**，禁止凭空编造色值或尺寸。
4. **定义布局系统**：写明全局框架（导航栏、公告栏、背景、右侧工具区）、容器宽度与居中方式、栅格与分区规则（如左上/左下/右三块、上下两栏）、卡片间距、响应式断点与多端降级策略。
5. **编排组件清单**：用表格列出全部可复用组件（按钮、输入框、卡片、进度条、弹窗、导航项、状态图标、分页、表格、下拉菜单等），逐项给出结构、视觉参数、状态、交互与来源编号。按钮分级、输入框聚焦态、状态色分级等必须单列。
6. **逐页规格**：为 `manifest.json` 的每个界面写一节，包含区域划分、字段清单与文案、数据来源（mock 字段）、状态分支（空态/有数据/异常/权限差异）、跳转与弹窗触发关系、对应的截图路径。
7. **交互与状态机**：把跳转、弹窗轮询、表单校验、刷新、复制、下载、取消订单、切换主题与语言等行为整理成「触发 → 结果」清单，标注涉及的界面与组件。
8. **资源映射**：把 `scan/assets/**` 的路径映射到具体使用位置，写明缺省处理（例如无图片 URL 时显示默认图标、公告无自定义背景图时使用默认背景）。
9. **实现约束**：给出 Vue3 + TailwindCSS 的映射原则（Token 落到配置或 CSS 变量、组件拆分粒度、路由与界面命名、mock 数据位置），但不写具体代码，不替 `web-maker` 决定工程形态。
10. **追踪矩阵与验收清单**：生成「描述编号 → 规范章节 → 验收项」矩阵；把每个可观察结果转成可勾选的验收项，含「细节与修复项」的全部条目。
11. **自检**：逐条执行质量检查，未通过则修正对应章节。

## 编写规则

- **不新增需求**：规范中不得出现 `webui-theme.txt` 未描述的功能、页面、字段或业务规则；为实现必需的工程性内容（路由、构建配置、mock 数据结构）单列在「实现约束」并注明「工程必需，非界面需求」。
- **不丢失细节**：所有原文案、单位、默认值、颜色语义、状态分支、跳转目标必须在规范中出现，追踪矩阵中不得有未映射编号。
- **参数具体**：禁止「合适的间距」「较大的圆角」等模糊表述；颜色用十六进制或 rgba，尺寸用 px/rem，动效写明曲线与时长。
- **状态完备**：每个界面列出全部状态分支；「未观察到」的内容写入「待确认」表，不写成确定规范。
- **章节齐全**：模板中的章节即使内容为空也保留标题并写明「无」或「待确认」，方便 `web-maker` 稳定解析。

## 质量检查

- [ ] 模板全部章节存在，标题层级与模板一致，无残留占位符与填写提示。
- [ ] 追踪矩阵覆盖全部 `D-xxx` 编号，无孤立条目。
- [ ] 每个 Token 都有具体数值与来源（描述编号或 `scan/` 证据路径）。
- [ ] 组件清单覆盖叙述中出现的所有控件，含各自主态、悬停态、聚焦态、禁用态与空态。
- [ ] 逐页规格的页面集合与 `scan/manifest.json` 的 `pages` 一致。
- [ ] 「细节与修复项」每条都进入验收清单。
- [ ] 「待确认」表中的问题已向使用者提出并记录答复；未答复项不得写成确定规范。
- [ ] 全文不含 Vue 组件代码、不含工程依赖清单。

## 失败与降级

| 情况 | 处理 |
| --- | --- |
| `webui-theme.txt` 缺失或未通过检查 | 停止执行，回到 `web-scan` 修复 |
| 描述含糊或自相矛盾 | 列入「待确认」表并询问使用者，禁止自行选定一种解释 |
| 缺少计算样式证据 | 结合截图给出候选值并标注「待确认」，不伪称来自原站 |
| `scan/assets/` 路径失效 | 在资源映射中保留原始 URL 并写明占位资源策略 |

## 与其他组件的边界

- 不重新扫描网站、不修改 `webui-theme.txt`、不修改 `scan/**`。
- 不生成工程代码、不决定 `projectType`；工程形态由 `pipeline.json` 与 `web-maker` 决定。
- `copy-themeUI.md` 一旦定稿，`web-maker` 必须严格实现；若实现阶段发现规范缺漏，回到本组件补写，禁止在代码中私自补足需求。

## 扩展点

后续可追加的独立能力：设计 Token 导出为 JSON、组件 API 契约生成、可访问性规范、多主题（暗色）章节、自动化一致性校验脚本。以新组件或模板新版形式登记。
